# Source play-selection countdown

The required Game workflow runs `test_ci.py`, then `run.py --controls --workers 2` with
its existing pinned kernel/M1, impact, normal camera, speech, HUD and FX inputs
and the authenticated `possession-service-original` directory. No new original
download or generated payload belongs in Git.

Canonical relative authority paths and their absolute equivalents are normalized
before the same strict root, file, symlink and Git-blob checks. Symlink aliases and
parent-traversal aliases remain rejected; no source-acquisition input is added.

`oracle.py` verifies thirteen fixed Git blobs before extracting unchanged
`timedown_play_select`, `flash_text_proc`, source suspension/resumption and
selected caller/choice bodies. The authored C bindings retain logical
int32 text handles, source arguments, sound operands and service order.
Seventeen traces compare every one of10,417 dispatches with the production
timer on the actual portable process host. Eleven separate original-C caller
checks cover current choice, already chosen, PAT, custom fallback and the
no-human bypass and the caller's already-pending sleep1 at force completion.
Those bindings do not implement native custom decompression,
native rendering, a target PRNG, ABI or DSP playback.

The production integration uses actual `GameSimulation`, genuine camera and
asset services, cabinet input buffer, selector, fixed-step bridge and HUD.
Kickoff and public Continue reach menus without private-state injection.
Eleven cases cover timeout/zero grace with FX on/off, page/slot/offensive flip,
selected-side protection, early completion, new/active-menu restart,
instruction predicate input, human/CPU order and explicit failures.
The portable menu does not produce the native tutorial UI.

The inherited kick-meter, combined fire/kick and match-lifecycle runner guards
require the complete 78-file pure production closure, including
`SourcePlaySelectionTimer.cs`. The combined fire/kick closure still adds its
seven existing consumer files, for 85 total; no prior source or control is removed.

All twenty-one inherited timer mutations and twenty-one additional random-controller
mutations compile in isolated source/output trees.
Compiler errors, missing original material, corrupt child receipts, unknown exit
statuses and wrong assertions cannot count as kills. The explicit `--workers`
argument accepts only one or two; **omitting it is serial**, irrespective of the
mutation-worker environment used by other campaigns. CI explicitly selects two.
Each control has its own source, compiler response, assembly, temporary/runtime
directory and output root. No build server or nested campaign is started.
Receipts retain inventory order, not worker completion order.

The runner compiles C#7.3 with optimization and warnings-as-errors, requiring zero
compiler diagnostics. It does not override the runtime's tiered-JIT defaults.
The final full baseline reexecutes this invocation's verified unchanged baseline
assembly in a new output root; it never reuses a previous run or an acceptance
receipt. Every mutated control still compiles separately. After controls finish,
the final full baseline and the independent, internally serial main40/current
default-compatibility builds share the same explicit one/two-worker bound.
There are never three concurrent managed build/execution children.

Negative controls use a fixed, explicit 42-control scope contract in both Python
and C#. The immutable control identity/expression/expected-failure inventory is
hash-checked. Required kills are pinned to the exact retained assertion line or
original-C difference case/field/row, never whichever failure happens first.

For the inherited timer controls, `timer-traces` executes all17 actual production
timer traces without loading/running unrelated ordinary-Core positive cases.
All17 completed traces are compared to unchanged original C, including when more
than one differs. Integration-only controls execute precisely their existing
timeout, highlighted-side or timer-output-failure case, with its complete ordinary
input setup, source fixture, ticks and independent original predicate unchanged.
Random controls retain their exact random or lifecycle case. This is negative-only
scheduling: no production state/counter/RNG injection or expected-failure weakening.
Its equivalence requires the independent Quality gate's explicit review.

The managed entry point requires both scope and control identity, the exact
17-case/10417-dispatch timer inventory and complete distinct 33-case random
inventory. Unknown, empty, omitted, multiple, wrong or substituted bindings fail.
`execution-scope.json` records admitted control, requested cases and the actual
started/completed case prefix, including failed cases. These executed negative
cases are separate from full-baseline counts; partial scope can never qualify a
full baseline. Missing/corrupt scope receipts or output errors fail the runner.
Both full baselines still independently execute every timer, actual caller,
random and lifecycle case with exactly42424 assertions and all original-C
comparisons. The ledger also names the pre-existing standalone gesture
reproduction, previously absent from the case arrays; it is not a new scenario.
The original C's separate eleven caller checks and491-draw default compatibility
remain mandatory.

## Cabinet RANDOM_SELECT

The same required command additionally executes thirty-three public cabinet cases
against the unchanged active `play_select_cntrl`, choices, CPU completion,
page tables/setup, `off_captain`, timer and parent spawn/wait/cleanup. The original
`qcreate` wrapper also executes; native stack allocation/dispatch and drawing remain
authored logical bindings, not target ABI evidence. `random_oracle.py` verifies the
existing thirteen inputs plus the already-acquired `PlayStuf.c` and `pmisc.c`.
No new original download, source body or numeric oracle fixture is checked in.

The gesture arms on the second separate left push at slot0, then starts with a
fresh C press while still left. It starts at slot5 without changing page. Core,
not the selector/input/render adapter, owns the direction/action draw pairs and
separate sleep1/sleep2 continuations. The fifteenth iteration consumes its final
pair before choosing; flips cap at four and page actions at six. Both-side draws
follow the actual side1-before-side0 head insertion. Timeouts include the real
parent's final sleep1 and its ordered CPU completion if a controller is still
sleeping. No synthetic B edge or invented menu process is used.

Cases include both roles/all four directions, two/four stations and captains,
single teammates, selected-side preservation, page3/preflip, hidden cursor,
ignored physical buttons during the walk, nontriggers and real consumer suspension.
The suspension fixtures call the existing actual Core process host's suspend/resume
services; they never change phase, tick, RNG, source indexes or continuation counters.
Four additional actual lifecycle cases cover redraw/host pause, restart and
explicit selection-dependency/output failures, including fail-stop/no retry draws.

The original cases compare raw requests/order/ticks, source sound operands/order,
page/slot/play choices, every admitted flip state and parent completion. Sound is
metadata, not instruction-granular native sound execution or PCM/DSP playback.
The existing portable configuration has four ordinary offensive pages and no custom
inventory/playbook/always-QB/receiver powerups; original custom-page record conversion
remains explicitly unsupported, not replaced by a random fallback.

`compatibility.py` authenticates main40 commit/tree and separately compiles it and
current production. The same authored untriggered seed1 script runs1,200 host steps
through actual kickoff, menus and live play. Host/player/process/HUD bytes, menu
events and **every** shared RNG call must be byte-identical. This is neither a
new public replay recording nor full M1 qualification. All three existing public
recordings, gzip/recipes, controller, seed and unfiltered vector remain immutable.
The inherited generation helper separately pins the new78-file production source
and retains the timer recording's original source pin; its four probes and full
current M1 stage are not removed or relabelled.

The real prepared `SourcePlayer.Checks` also supports `--random-selection-only`:
ordinary `PlayerHost.Capture`/Continue reach and perform the gesture, validating the
real selected-page/slot HUD reflection, thirty shared draws, source sound metadata,
redraw and restart. A recording render sink is not browser or Unity player proof.
