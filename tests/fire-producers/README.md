# Real Source57/M1 fire producers (explicit authored opt-in)

This suite executes the actual M1 factory, Core mode/catch/ball/result/selection
callers and approved FX runtime. It is not a public replay or native scheduler.
The source helper/process/material/scope suite remains in `tests/fire-spfx`;
its 18,800 assertions and 16 controls are retained.

```sh
python3 -B tests/fire-producers/run.py \
  --fixture "$C1_FIXTURE" --sound "$SAFN" --m1 "$M1_INPUTS" \
  --bundle "$AUTHENTIC_FIRE_BUNDLE" --manifest-sha256 "$FIRE_MANIFEST_SHA" \
  --reference-proof tests/fire-spfx/.artifacts/module-baseline/evidence.json \
  --output tests/fire-producers/.artifacts/callers
```

`mutations.py` accepts the same inputs (and a new output). Its compiled controls
target actual recurrence, edge-only emission, paired-cache production, lineup
scope, catch, post-increment ball, latch reset, disabled RNG, selection group,
and declared level-zero order. Compile errors are not kills. Actual Core
emitter inputs/ordered requests/draws are also compared to the unchanged pinned
`maybe_plyr_fire` C body from the module proof; the helper's logical tick is
not relabelled as a native clock.

## Immutable feature API

All old defaults remain disabled, including Portable index compatibility.
Fire, portable-authored kick meters and Portable index compatibility are
independent. Pass the named optional `fireEffects` argument only to the actual
M1 source constructor/factory; the combined suffix is `fireEffects`, then
`kickMeterMetrics`:

```csharp
var fire = new SourceFireGameplayConfiguration(
    new SourceFireSpfxRuntime(authenticatedBundle),
    logicalPcountAtTickZero: 0,
    authoredCull: SourceFireCull.Off);
// SourceC2Composition.CreateM1Simulation(existingArguments..., fireEffects: fire)
```

The actual Unity host URL is:

```text
?sourceprofile=original-teams-contact281-c2-m1&source-compatibility=portable&source-fire=portable
```

Missing/`disabled` means no FX; invalid/duplicate values and unsupported resource
profiles reject. The Unity host requires the real imported F asset plus the
explicit authored actor-white shader reference. The importer binds both real
shaders; an older asset without the new reference fails loudly when opted in.
No asset/Editor execution is performed by these tests.

`GameSimulation.SourceFireEnabled` distinguishes unconfigured state.
`SourceFireFrame`, `SourceFireProcesses`, and `SourceFireRecords` are null when
disabled; enabled reads return immutable snapshots without RNG or simulation
advancement. `SourceFireSoundSubmissions` retains ordered original direct-call
metadata per tick, deliberately not resubmitted through an unrelated VM
binding or claimed audible DSP playback. `SourceBallEffectSelection` returns
the sticky nonfire selection to the ball owner. That owner now applies the
original `BF_WHITE` write on each post-increment flight-time multiple of ten
selected as Blink. The existing next free/phantom wake clears it; held balls,
sticky Bobble selection and play-over priority retain their original behavior.
This stays behind the existing independent fire opt-in. The separate nonfire
trail objects remain unimplemented, not substituted with generic particles.

The caller suite retains its original **40 assertions** and adds **171** owner
assertions: 25 ordered enabled cases plus disabled/default controls. The actual Core inputs and outputs are
also compared to the unchanged original free/phantom guard, flight increment,
white clear, sticky selector and blink write, extracted from the selected
module proof's SHA-pinned `originalInputs.player`. No source/cases are shipped.
These are declared component states, not public gameplay or native scheduling.
The five new compiled controls reject a dropped write, wrong cadence, lost
sticky Bobble selection, omitted next-wake clear and an illegal held-ball write.
All ten existing producer controls remain required. Asset-free inventory,
shape, pin and control-anchor guards run in the existing Game source checks;
they are not counted as actual gameplay or original-C execution.

## Real ordering, cache, and consumer path

* M1's two original bank draws still precede initial AI. The effect runtime is
  explicitly initialized at logical tick0 before the first kickoff lineup.
* Every real source tick, including selection, visits known head-inserted FX
  nodes, then individual current C2 whistle continuations, then `game_proc`.
  This is **portable-authored ordering**, not a target qsort/tie witness.
  Births remain sleep1, never inline. Existing disabled dispatch is retained.
* Actual Core `SourceDraw`/the same provider owns every `randrng` request.
  Actor/ball producer sites execute in their existing player/ball phases.
* The real `CameraJoints` producer retains all15 joints with that very camera
  matrix/position/tick before contact. FX first-wake inverse reconstruction
  uses that immutable pair, never new bones/current-camera substitution.
  Older cache is admitted only for actual Core `PlaySelect` suspension.
* Completed source work captures one immutable frame. Unity sends it to
  `SourceFireSpfxRenderer.ConsumeAfterSourceStep` on the actual simulation-step
  callback; skipped host frames hold it. Restart clears the rendered epoch.
* Actual raw0x400 drives the existing team/rig material path only when enabled.
  The original texture is used, source constant `0xc0000000` is represented by
  a labelled authored Unity white-add shader, and exact original materials are
  restored when clear. This is not a tint fallback or a claim about native
  Glide combiner precision, alpha association or native pixels.

The current Core owns full lineups (`side=-1`); its typed side adapter also
preserves side0/side1 scope. A native one-team audible producer is not invented
where Core currently has no audible input/lineup path. Integration of such a
future path must pass its actual side. Original global latches reset separately.
Current Core's interactive selection contract does not model arbitrary native
`pup_noplaysel` continuations; do not treat this slice as cabinet menu fidelity.

The code does not qualify native pcount/global process ordering, target RNG,
non-FX global draw ordering, TEXUS/WMS output, native player combiner/FPU
precision, DSP, Unity import/build/pixels, browser deployment or a full match.
Browser integration is a separate lease around this frozen producer interface.

The [combined runtime suite](../fire-kick-integration/README.md) additionally
executes all four fire/kick combinations and mixed lifecycles. Its stock full
M1 default-preservation run keeps both features disabled; it is not a new
full-match fire qualification or browser installation.
